Events und Session-Decks

Ein Event ist die öffentliche Hülle einer Session: Titel, Zeitraum, Status und sechsstelliger Join-Code. Der Code ist zugleich der Session-Code (sessionCode). Das Deck (Folienfolge) liegt nur in der Session — nicht im Event-Datensatz. Es gibt keine parallelen „Sets“ mehr; pro Event genau ein Deck.

Team-Zuordnung

Jedes Event gehört genau einem Team. Alle Mitglieder dieses Teams können das Deck und alle Folien bearbeiten sowie präsentieren — ohne separates Passwort oder Entsperrkennwort. Beim Anlegen wählen Sie das Team aus; Administratoren können das Team später ändern.

Angemeldete Teammitglieder nutzen ihr Konto; der frühere Admin-Schlüssel pro Event entfällt. Ad-hoc-Sessions ohne Event behalten optional den Admin-Schlüssel.

Startuhrzeit und Countdown

Optional können Sie eine Startuhrzeit setzen. Auf der Leinwand (#/stage/<code>) und in der Presenter-Ansicht erscheint dann ein Countdown mit Tagen, Stunden, Minuten und Sekunden. Unter 5 Minuten erscheint der Hinweis „In wenigen Augenblicken geht es los…“. Bei 0 wechselt die Ansicht automatisch zur ersten Folie. Presenter können den Countdown überspringen.

Event-Grafik

Optional eine Hintergrundgrafik (PNG, JPEG, WebP, SVG, max. 2 MB, empfohlen 1920×1080). Beim Upload wird auf max. 4096 px Breite skaliert. Die Grafik erscheint dezent hinter dem Countdown. Ohne Grafik gilt der Branding-Farbverlauf.

Administration

  • Events (#/admin/events) — Liste, Anlegen, Metadaten, Statistik, QR, Einladungstext
  • Neues Event — nach dem Speichern Weiterleitung zum Session-Deck
  • #/admin/sessions/<code> — Deck-Editor (siehe unten)
  • Sessions (#/admin) — ad-hoc-Session ohne Event-Karte auf der Startseite

In der Admin-Menüleiste ist beim Deck-Editor der Punkt Sessions hervorgehoben (nicht Events), weil Sie dort die Folien der Session bearbeiten.

Deck-Editor — Folien bearbeiten

Unter #/admin/sessions/<code> pflegen Sie die gesamte Folienfolge (max. 40).

Inhalt ändern
Stift-Icon oder Doppelklick auf den Titel. Einfache Typen (Multiple Choice, Bewertung, Wortwolke, Freitext, Q&A): Inline-Editor in der Zeile. Komplexe Typen (Quiz, Ranking, 100 Punkte, Bildwahl, Terminfindung, Picker): Modal mit allen Feldern — beim Picker inkl. Kategorien-Editor und Live-Vorschau. Alt+Stift öffnet immer das Modal. „Alle Felder…“ wechselt vom Inline zum Modal.
Speichern
Button oder Ctrl/Cmd+S. Nach 30 s Pause ohne Tippen: Auto-Save. Beim Schließen mit ungespeicherten Änderungen erscheint eine Warnung.
Löschen
Mit Bestätigung. Anschließend Toast mit Rückgängig (5 Sekunden) — stellt den Inhalt wieder her (Live-Stimmen entfallen).
Mehrfachauswahl
Checkboxen neben den Folien; Shift+Klick wählt einen Bereich. Bulk: Eigenschaften… (Reveal, geplante Minuten, Notizen), duplizieren, löschen.
Reihenfolge
Drag & Drop oder Pfeil-Buttons.
Shortcuts
↑/↓ Fokus · Ctrl/Cmd+E bearbeiten · Ctrl/Cmd+D duplizieren · Entf löschen

Status

Geplant
Event sichtbar auf der Startseite, Join für Teilnehmende noch gesperrt. Staff (Presenter) darf testen.
Aktiv
Join freigegeben — Teilnehmende nutzen #/join/<code> oder die Event-Karte.
Abgeschlossen
Ergebnisse/Einblick; Join weiter möglich für die bestehende Session.
Archiviert
Nicht mehr auf der Startseite gelistet; Join für Nicht-Admins blockiert.

Statuswechsel per Zeitplan (stündlich) oder manuell im Event-Detail. Kein E-Mail-Versand — nur Audit-Eintrag.

Startseite und Join

Öffentliche Karten unter „Aktuelle Events“ / „Vergangene Events“ mit QR, Join-Link und Copy-Text. Teilnehmer-Link zeigt immer auf die Session (#/join/123456), nicht auf eine Event-ID. Alte Links #/event/<id> leiten auf den Join-Code um.

Folien kopieren

Im Deck-Editor: Modal Folien kopieren — Quell-Session wählen (andere Events oder Sessions), optional einzelne Folien. Maximal 40 Folien je Session. Beim Anlegen kann optional ein bestehendes Event als Vorlage dienen (copyFromId).

Event-Branding

Optionales Logo/Farben/Footer pro Event überlagern die Instanz-CI in Join- und Presenter-Ansicht — nicht die globale Branding-Seite.

Löschen

Nur bei Status geplant oder archiviert. Sessions und Umfragedaten bleiben in pulse.db, bis die Aufbewahrungsfrist greift.
