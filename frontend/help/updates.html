Automatische Updates

Unter Updates (#/admin/updates) prüft Pulse regelmäßig GitHub-Releases und kann neue Versionen mit Backup installieren. Nur Administratoren dürfen Updates auslösen.

Voraussetzungen

  • UPDATE_REPO=owner/repo in der .env (z. B. markusringe/pulse)
  • UPDATE_ENABLED=true für automatische Hintergrund-Prüfung
  • Optional GITHUB_TOKEN für höhere API-Limits (60 Requests/Stunde ohne Token)
  • Prozess-Manager (systemd, Docker restart: always) startet den Server nach dem Update neu

Manuelles Update

  1. #/admin/updates öffnen
  2. Jetzt prüfen — lädt das neueste GitHub-Release
  3. Release-Notes lesen (Breaking Changes rot markiert)
  4. Update jetzt installieren — Backup wird automatisch erstellt
  5. Server startet neu; danach Health-Check unter /api/health

Rollback

In der Update-Historie kann für erfolgreiche Installationen der letzten 7 Tage ein Backup wiederhergestellt werden.

Update fehlgeschlagen?

  • GitHub nicht erreichbar — später erneut prüfen
  • npm install schlägt fehl — Node-Version prüfen (≥ 22), Logs im Server-Output
  • Bei Installationsfehler wird automatisch das Backup eingespielt
  • Manuelles Rollback über die Historie-Tabelle

Entwickler: Release erstellen

  • Semantische Version in package.json erhöhen
  • Git-Tag v1.3.0 setzen und GitHub-Release veröffentlichen (kein Draft)
  • Breaking Changes in den Release-Notes mit Breaking markieren
  • SQL-Migrationen unter migrations/*.sql ablegen
