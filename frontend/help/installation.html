Installation und Betrieb

Pulse läuft als Node.js-Anwendung — lokal zum Testen oder auf einem Server mit Docker. Ausführliche Schritte stehen in docs/installation.md im Repository.

Lokal (Entwicklung)

  • Voraussetzung: Node.js ≥ 22, npm
  • chmod +x scripts/install.sh (einmalig)
  • ./scripts/install.sh oder npm run setup — installiert Abhängigkeiten, legt .env an, setzt ADMIN_SECRET
  • npm start → http://localhost:3000
  • Healthcheck: /api/health

Ohne exportierte .env-Variablen startet der Server nur mit einem Entwicklungs-Pepper — in Produktion immer ADMIN_SECRET setzen.

Docker Compose (lokal oder Server)

  • ./scripts/install.sh --docker — baut Images, seedet data/, startet den Stack
  • Stack: zwei App-Instanzen (pulse, pulse-b), Redis, nginx (Port 80/443), optional Prometheus und Grafana (Port 3001)
  • Pulse erreichbar über http://<host>/ (nginx)
  • Daten liegen im Host-Verzeichnis ./data (SQLite pulse.db, Branding, Events, SSL unter data/ssl/)

VPS Ubuntu (Produktion)

Auf einem frischen Ubuntu 22.04 / 24.04 Server (als root oder mit sudo):

chmod +x scripts/install-vps-ubuntu.sh scripts/seed-data.sh
sudo ./scripts/install-vps-ubuntu.sh

Alternativ: npm run setup:vps (im Projektverzeichnis, mit sudo).

Das VPS-Skript installiert Docker Engine und das Compose-Plugin, richtet die Firewall (UFW: SSH, 80, 443) ein, erzeugt .env mit Zufallssecrets, kopiert Grundeinstellungen nach data/ und startet docker compose up -d.

  • Grunddaten (scripts/seed-data.sh): branding.json und privacy.json (Saarbrücken-Preset), leerer Event-Katalog, leeres Audit-Log — bestehende Dateien werden nicht überschrieben
  • Zugangsdaten nach der Installation: INSTALL-CREDENTIALS.txt (ADMIN_SECRET, Grafana-Passwort) — sichern und danach löschen
  • Option --expose-grafana öffnet Port 3001 in der Firewall
  • Option --git URL --dir /opt/pulse klont das Repository und installiert dort

HTTPS nach der Installation

DNS auf den Server zeigen lassen, Port 80 von außen erreichbar, dann in der Admin-Oberfläche SSL (Let’s Encrypt HTTP-01). Details: SSL-Hilfe.

Instanz-Admin vs. Session-Admin

  • ADMIN_SECRET (Umgebungsvariable / .env): API und Menüs Branding, Datenschutz, SSL, Einstellungen — Header X-Admin-Key oder Bearer
  • Session-Admin-Schlüssel: pro Session beim Start, bleibt im Browser — Folienwechsel und Moderation

Aktualisierung

git pull, dann docker compose build && docker compose up -d (Docker) oder npm install und Server neu starten (lokal). Daten in data/ bleiben erhalten.
